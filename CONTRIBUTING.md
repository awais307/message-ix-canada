We appreciate contributions of all forms, including bug reports, feature suggestions, documentation improvements, and code contributions. Please read through the guidelines below to get started.

## Getting Started

1. **Fork the Repository:** Create your own copy of the repository by forking it to your GitLab account.
2. **Clone the Repository:** Clone your forked repository to your local machine:
   ```bash
   git clone https://gitlab.com/SESIT/message-ix.git
   ```
3. **Install Dependencies:** Follow the setup instructions in the `README.md` file to install any necessary dependencies.
4. **Create a Branch:** Create a new branch for your work:
   ```bash
   git checkout -b feature/short-description
   ```

## Issues and Feature Requests

### Reporting Bugs
If you find a bug, please create an issue in the GitLab Issues tab. Include:
- A clear and descriptive title.
- Steps to reproduce the issue.
- Expected and actual results.
- Screenshots or logs (if applicable).

### Requesting Features
To request a new feature, create an issue with:
- A detailed description of the feature.
- The problem the feature solves.
- Any additional context or suggestions.

## Contributing Code

### Development Workflow

1. Ensure your local repository is up-to-date:
   ```bash
   git fetch origin
   git checkout main
   git pull origin main
   ```
2. Make your changes in your feature branch.
3. Test your changes thoroughly.
4. Commit your changes:
   ```bash
   git add .
   git commit -m "Brief description of your changes"
   ```
5. Push your branch to your forked repository:
   ```bash
   git push origin feature/short-description
   ```
6. Create a merge request (MR) from your branch to the main branch in the original repository. Provide a clear title and description of your changes.

### Coding Standards

- Follow the coding style used in the repository (e.g., PEP 8 for Python).
- Write descriptive commit messages.
- Include comments and documentation where necessary.
- Test your changes before submitting an MR.

## Documentation Contributions

If you wish to contribute to the documentation:
- Make sure all changes are clear and concise.
- Update any relevant sections in the `README.md` or other documentation files.
- Use proper markdown syntax.
